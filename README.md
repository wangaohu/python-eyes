# python-eyes

一个用 150 行 Python 写的**实时颜色识别与计数**小工具：打开摄像头，实时框出画面里的红/绿/蓝/黄色块，统计数量，并把每一次识别结果写进 CSV 方便回看。

这是我的第一个视觉项目，目标不是做一个成品，而是验证一件事：**我能不能自己把"看到一个东西"变成"机器能识别的数据"。**

（这里放一张运行截图 / 演示 GIF）

## 运行环境

- Python 3.10+
- 依赖：`numpy`、`opencv-python`

如果还没装依赖：

```bash
python -m pip install numpy opencv-python
```

## 怎么运行

```bash
python main.py                # 使用默认摄像头
python main.py --camera 1     # 换一个摄像头
python main.py --no-window    # 不弹预览窗口，只写日志
```

运行后窗口里按 **q** 退出。退出时会打印处理了多少帧、平均 FPS、每种颜色检测到多少次。

## 输出

运行时会生成 `log.csv`，记录了每一次识别的时刻、颜色、位置、尺寸和面积：

| timestamp | color | x | y | width | height | area |
| --- | --- | --- | --- | --- | --- | --- |
| 1730000000.12 | red | 210 | 160 | 180 | 175 | 31500 |

有了这个文件，我就可以回头分析"哪种颜色最容易被误检"，而不是凭感觉调参数。

## 原理（三句话）

1. 把摄像头的一帧从 BGR 转成 **HSV** 色彩空间——HSV 把"是什么颜色"和"有多亮"分开，比 RGB 更抗光照变化
2. 用 `cv2.inRange` 按颜色的 HSV 范围做**二值化**，得到一张只有目标颜色的黑白掩膜
3. 在掩膜上找**轮廓**，按面积过滤掉噪点，剩下的就是真正的色块

## 踩过的坑

- **误检太多**：一开始画面里到处是噪点，框得到处都是。解决办法是先腐蚀再膨胀，再加一个面积阈值（`AREA_MIN`），小碎块直接丢掉。
- **FPS 偏低**：一开始只有十几帧。把分辨率固定到 640×480、减少每帧的重复转换之后，FPS 提到了 25 左右。
- **OpenCV 画不了中文**：`cv2.putText` 只支持 ASCII，屏幕上的标签只能用英文，中文说明放在日志和 README 里。
